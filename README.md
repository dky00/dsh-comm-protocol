# dsh-comm-protocol

给 DSH 装一份**沟通协议**：模型在动手之前，先把你真正要什么弄清楚。

## 背景

大模型有个很稳定的倾向：把用户的单句话当成任务清单，立刻产出一个结构完整、看起来权威的方案。方案本身未必有错，但方向可能从一开始就是偏的。

方向错的东西很难被推翻。它不像胡话那样会被一眼否掉，而是被部分采纳；没被纠正的部分会变成后续所有对话的隐含前提，越走越远。

这个插件把一份写好的协议注入 system prompt，要求模型在给出任何方案之前，先锁定会改变结论的前提，并说出它对需求的理解、以及自己最可能错在哪里。

## 什么效果

- 需求尚未对齐时，不给方案、不给步骤清单，而是先把影响结论的条件问清楚，并且一次性问完。
- 会主动说出「我认为你要的是什么」和「如果我读错了，最可能错在哪」，让你能低成本地否定它。
- 你确认之后才进入实现讨论；即便确认了，下一个动作也是问要不要开始，而不是直接开做。

新会话的第一条回复开头会带一个标记，其中包含当前协议的版本和档位。看到它即表示注入成功。

## 怎么使用

装完即用，不需要额外配置。

当你就某件事征求意见或要方案时，它会按上面的顺序走：问清前提 → 说出理解与风险点 → 等你确认 → 再谈怎么实现。

想关掉，或者只是想闲聊，改配置文件即可：

```
~/.dsh/comm-protocol/config.json
```

```json
{
  "enabled": true,
  "mode": "explore",
  "expectVersion": "0.4.0",
  "probe": false
}
```

| 字段            | 作用                                                         |
| --------------- | ------------------------------------------------------------ |
| `enabled`       | 总开关。关闭时这段文字**完全不在**模型上下文里               |
| `mode`          | `align` 只做对齐 / `explore` 边聊边收窄 / `deliver` 直接交付 |
| `expectVersion` | 正文版本校验，对不上就不注入                                 |
| `probe`         | 打开后每轮注入一个随机标记，用于验证确实送达                 |

**改完不用重启**，下一轮生效。

协议正文在 [`protocol/PROTOCOL.md`](protocol/PROTOCOL.md)，可以改成你自己的规矩。若改动了文件开头的 `version:`，需同步 `expectVersion`，否则协议会停止注入——这是有意为之：版本对不上，说明文档不是你以为的那一份。

## 怎么安装

### 一、从插件市场装（推荐，桌面版也能用）

1. 打开 **插件** 页，点「实验性插件」旁边的**更多**，把**自定义插件市场**打开
2. 回到插件页，进**发现**标签，点**添加索引源**，填入：

```
https://dky00.github.io/dsh-comm-protocol/market/index.json
```

3. 找到「沟通协议」，点安装。确认框里会显示来源：Git 仓库和一个 commit——**核对一眼**，那就是会装进你机器上的代码
4. 重启 DSH

### 二、命令行（只对 `web` 这类能被 CLI 管理的 profile 有效）

```powershell
dsh plugin --profile web add git+https://github.com/dky00/dsh-comm-protocol.git#117c9d17256e3160af580185cee84f11a148e0fb
```

带上完整 commit 是为了装到的代码和索引里钉的完全一致。省略它写成 `github:dky00/dsh-comm-protocol` 也能装，但那拿的是默认分支的最新提交——别人装到的可能就不是你试过的那份了。

`--profile desktop` 会被拒绝（桌面版 profile 由应用独占管理），桌面版请走市场。

卸载：`dsh plugin --profile web remove dsh-comm-protocol`

### 装完之后

**重启 DSH**。首次加载会自动创建配置并开启，不需要手写任何文件。新会话的第一条回复开头会出现一个带版本和档位的标记，看到它就说明生效了。

如果一直等不到那个标记，看 `~/.dsh/comm-protocol/status.json`——它是每轮装配后重写的，里面写着当前状态和实际注入的字符数。
